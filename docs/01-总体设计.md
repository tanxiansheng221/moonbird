# 《怒鸭大战》总体设计文档

> 项目代号：moonbird（月鸟）
> 技术红线：全程仅使用 MoonBit 语言开发（赛事硬性要求）
> 目标赛事：2026 MoonBit 九月黑客松（验收截止 9 月 30 日）

## 1. 项目定位

一款弹弓物理射击网页游戏（玩法致敬愤怒的小鸟，角色/美术/命名全部原创），
同时沉淀三个可复用产物，满足赛事"工作有效性"要求：

1. **可复用的 2D 物理模块**（重力积分、圆/矩形碰撞、材质破坏系统）
2. **游戏循环模板**（固定步长更新 + WASM-4 渲染回调的标准骨架）
3. **像素渲染封装**（WASM-4 framebuffer 上的程序化绘制工具集）

## 1.5 实现演化（设计 → 落地，重要）

本文档 §3 的模块划分是**立项时的 WASM-4 方案设计稿**。实际开发中架构演化为
**双形态实现**（物理核心共用）：

```
wasm4demo/
├── birdcore/   物理核心（纯 MoonBit，零平台依赖）—— §3 core 层的落地
│     Vec2 / Entity / 材质 / SAT 碰撞 / 冲量解算 / 休眠 / 爆炸链 / 伤害模型
├── webgame/    游戏逻辑主形态（MoonBit js target + Phaser 渲染薄壳）
│     状态机 / 12 关 / 4 种技能鸟 / 存档 / 音效 / exports API
├── maze/       WASM-4 原型形态（160×160 幻想机，物理正确性验证平台）
└── phaser/     Web 前端（加载 webgame.js，浏览器即玩）
```

演化理由：WASM-4 的 160×160/4 色约束利于验证物理正确性（maze 形态保留），
但完整 12 关体验需要更大视口与素材表现力 → 主形态迁移至浏览器（js target）。
**分层铁律不变**：birdcore 不依赖任何渲染/平台 API，可独立 `moon test`。

红线修订：原「无任何 .js 逻辑文件」修订为「**游戏逻辑 100% MoonBit**
（birdcore + webgame），.js 仅存在于渲染薄壳（Phaser 场景）与构建脚手架」。

## 2. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | MoonBit（唯一） | 赛事红线 |
| 运行时 | WASM-4 幻想主机 | 输入/音频/精灵/存档 API 固定，FFI 量极小；160×160 像素风降低美术成本 |
| 编译产物 | game.wasm | WASM-4 官方支持 MoonBit 后端 |
| 物理引擎 | 自研（不引 JS 库） | 引 Matter.js 即破红线；2D 简化物理自研量级可控 |
| 美术 | 程序化像素绘制 | 无外部素材，零版权风险 |
| 音效 | WASM-4 音调 API 程序化合成 | 零音频文件 |
| 存档 | WASM-4 disk API（1KB 持久存储） | 记录关卡解锁与星级 |
| 许可证 | MIT | 开源合规（验收硬指标） |

## 3. 模块划分

```
src/
├── core/            纯逻辑层，不依赖 WASM-4，可 moon test 单测
│   ├── vec.mbti     Vec2 向量运算
│   ├── physics.mbti 物理：积分、碰撞、冲量
│   ├── entity.mbti  实体：鸟/猪/方块/TNT 定义与状态
│   ├── material.mbti材质参数表（木/石/冰/TNT）
│   └── level.mbti   关卡数据结构 + 校验
├── game/            游戏层（依赖 core）
│   ├── slingshot.mbti 弹弓：拖拽→初速度、轨迹预览
│   ├── birds.mbti     四种鸟的技能逻辑
│   ├── damage.mbti    碰撞→伤害→破坏→得分
│   └── camera.mbti    镜头跟随
├── render/          WASM-4 绘制封装
│   ├── draw.mbti    调色板、矩形、圆、精灵绘制
│   ├── sprites.mbti 程序化精灵（鸟/猪/方块像素图）
│   └── ui.mbti      文本、按钮、星级
├── audio/           音效合成
├── input/           鼠标/触摸事件封装
├── storage/         存档读写（disk API，含 CRC 校验）
└── main.mbti        状态机 + 主循环入口
```

**分层铁律**：core 不得 import render/audio/input —— 保证物理可独立单测，
也是"可复用物理模块"这一卖点成立的前提。

## 4. 游戏状态机

```
Boot → Title → LevelSelect → Playing ⇄ Paused
                                  ↓
                          LevelClear（胜利结算，星级）
                                  ↓
                          LevelFail（失败，重来）
```

- Playing 内子阶段：Aiming（待发射）→ Flying（鸟飞行中）→ Settling（世界静止判定）→ 回到 Aiming 或结算
- 静止判定：所有动态实体速度低于阈值持续 1 秒 → 本回合结束
- 胜利：场上猪数为 0；失败：鸟用尽且有猪存活

## 5. 功能范围（完整版）

### 5.1 小鸟（4 种）
| 鸟 | 颜色 | 技能 | 触发 |
|---|---|---|---|
| 圆圆 | 红 | 无技能，基准弹道 | - |
| 疾风 | 黄 | 点屏瞬间加速 2 倍 | 飞行中点击 |
| 三兄弟 | 蓝 | 点屏分裂为 3 只小 | 飞行中点击 |
| 轰隆 | 黑 | 点屏或撞击后爆炸，范围伤害+冲量 | 飞行中点击/撞击延迟 0.5s |

### 5.2 结构方块（3 材质 + TNT）
- 木（脆，中等质量）、石（硬，重）、冰（很脆，轻，低温打碎）
- TNT：受大于阈值的冲击即爆炸（同黑鸟爆炸，不叠加连锁死循环——同一帧爆炸源去重）

### 5.3 关卡
- 关卡 **12 个**，难度曲线对齐愤怒的小鸟运行模式（完整版）
- 星级：1 星通关 / 2 星剩余≥1 鸟 / 3 星剩余≥2 鸟
- 解锁：串行解锁，进度存 WASM-4 disk
- 关卡设计模板（12 关分布）：
  | 关卡 | 主题 | 考察点 |
  |---|---|---|
  | L1 | 教学关 | 单猪单结构，只给红鸟 |
  | L2 | 木塔入门 | 红鸟×3，简单塔 |
  | L3 | 冰面初见 | 冰块易碎，红鸟×3 |
  | L4 | 石墙 | 引入石块，需红鸟×4 连击 |
  | L5 | TNT 狂欢 | 教 TNT 连锁，黄鸟首发 |
  | L6 | 黄鸟专用关 | 远距离高塔，考验加速时机 |
  | L7 | 蓝鸟冰窟 | 蓝鸟分裂打多冰块 |
  | L8 | 混合材质 | 木+冰+石混编 |
  | L9 | 城堡外墙 | 高血量结构，黑鸟首发 |
  | L10 | 黑鸟爆破关 | 密集石结构，炸弹清场 |
  | L11 | 全鸟混编 | 每种鸟都要用对 |
  | L12 | 终极王座 | 猪 Boss 位 + 全材质大城堡 |

### 5.4 得分
- 猪击杀 5000、方块破坏 500、剩余每鸟 10000
- 结算界面显示星级 + 总分 + 最高分（存档）

## 6. 美术方向（全程序化，零外部素材）

- 160×160 逻辑分辨率，WASM-4 调色板 4 色组 × 3 组，实际可用 4 色同屏（PALETTE 寄存器可动态换组）
- 小鸟：圆身 + 白色眼白 + 黑瞳 + 橙喙 + 内八粗眉（愤怒感的全部来源）
- 猪：绿圆 + 大鼻 + 两鼻孔，受损后表情变化（三档血量三张脸）
- 方块：纯色块 + 边缘暗线 + 材质纹理线（木=横纹 / 石=点刻 / 冰=斜高光）
- 背景：渐变天空 + 程序化草地起伏 + 远景山（两层视差）

## 8. 风险与预案

| 风险 | 预案 |
|---|---|
| 方块堆叠抖动（自研物理最大风险） | M1 就做堆叠压测场景；用位置修正 + 休眠机制（低速实体睡眠） |
| WASM-4 1KB 存档不够 | 存档只存 12 关星级（12×2bit）+ 最高分，压缩后 <32 字节 |
| 160×160 画面关卡装不下 | 镜头跟随 + 关卡坐标大于屏幕坐标，弹弓在原点，目标在右侧 320~480 区间 |
| 时间不够 12 关 | 关卡用数据表驱动，结构模板复用（塔/墙/城堡三套），12 关按模板拼装省时 |
